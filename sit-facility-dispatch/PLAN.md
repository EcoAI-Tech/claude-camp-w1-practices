> 目标：把「纸质派工单」变成「手机派单 + 现场反馈 + 电子签字闭环」的系统，真正落地到 Facility Department 日常使用，并托管到你的 GitHub。

> 本清单按阶段推进，每一步都能打勾。跟着做，做完就上线。

## 第 0 步：先做一个技术选型决策（10 分钟看懂）

你有两条路，先想清楚走哪条：

| 路线 | 适合 | 优点 | 缺点 |
|------|------|------|------|
| **A. 无代码平台**（钉钉/飞书/微信企业号 的「审批+任务」，或 Airtable + 表单） | 只想尽快用起来、不想写代码 | 1~2 天能上线、维护简单 | 定制性差、电子签字/流程不够灵活、数据在别人平台 |
| **B. 自建 Web App（推荐）** | 想要真正属于自己的系统、以后能扩展、还想练技术 | 完全可控、可定制、可对接后续系统 | 需要开发，第一次上线约 1~2 周 |

**本清单默认走 B 路线**，推荐这套「零成本、对新手友好、能长期用」的技术栈：

- **前端 + 后端一体**：Next.js（React 框架，手机端做成 PWA，装到手机桌面像 App）
- **数据库 + 登录 + 图片存储 + 实时推送**：Supabase（免费额度够部门内部用）
- **部署**：Vercel（免费、绑定 GitHub 自动上线）
- **通知**：先用 Web Push（PWA 推送）+ 邮件兜底，后期可接微信/短信

> 如果你更想走 A 路线，或者想用别的技术（比如小程序、Flutter），告诉我，我给你换一版清单。

## 第 1 步：把需求拆成「能落地的 MVP」

不要一次做全部。先做**最小可用闭环**，跑通了再加功能。

### 1.1 角色（两种人）
- **秘书 / 管理员**：录入任务、指派给员工、看进度、导出记录。
- **员工**：看今日任务、看详情、拍照反馈、完工签字。

### 1.2 MVP 必须有的核心闭环（第一版就要有）
- [ ] 秘书能建单：填写「地址 / 时间 / 优先级 / 故障描述 / 指派给谁」
- [ ] 员工手机登录后能看到「今日任务看板」
- [ ] 员工能点开任务看详情
- [ ] 员工干活中能拍照上传（问题反馈）
- [ ] 员工完工能拍照 + 留言 + 电子签字，系统记录完工时间
- [ ] 秘书后台能实时看到状态变化（待处理/进行中/已完成）

### 1.3 先「往后放」的功能（第二、三版再做，别卡在这里）
- ⏳ **任务智能分发**：第一版先用「秘书手动指派」。等数据跑起来，再加规则（按工种、按区域、按当前工作量自动推荐/自动派）。
- ⏳ 微信 / 短信通知（先用 App 内推送 + 邮件）
- ⏳ 报表统计、绩效分析
- ⏳ 员工之间的任务交接 / 协调排序

> **关键心态**：先让 10 个员工真的用起来，比功能做全更重要。

## 第 2 步：设计数据模型（系统的地基）

在 Supabase 里建这几张表（先照抄，够用了）：

**users（员工/秘书）**
- id、name、phone、role（`employee` / `secretary`）、trade（工种，如水电/木工）、active

**tasks（任务单）**
- id、title（简述）、description（故障详情）、address（地址）、
- priority（`urgent`/`high`/`normal`/`low`）、scheduled_time（预约/期望时间）、
- status（`pending`/`assigned`/`in_progress`/`done`/`cancelled`）、
- assigned_to（指派给哪个员工 id）、created_by（秘书 id）、
- created_at、started_at、completed_at

**task_updates（过程反馈 / 完工反馈）**
- id、task_id、user_id、type（`progress`/`completion`）、
- note（文字留言）、photo_urls（图片，存 Supabase Storage）、created_at

**signatures（电子签字）**
- id、task_id、user_id、signature_image（签名图片）、signed_at

> 图片和签名都存到 Supabase Storage，表里只存链接。

## 第 4 步：搭项目骨架（第 1 天）

- [ ] 用 Next.js 初始化项目：`npx create-next-app@latest sit-facility-dispatch`
- [ ] 装 Supabase 客户端：`npm install @supabase/supabase-js`
- [ ] 配好环境变量 `.env.local`（放 Supabase URL / key，**不要提交到 GitHub**）
- [ ] 在 Supabase 里按第 2 步建表，并开启 **Row Level Security（RLS）**（保证员工只能看到自己的任务）
- [ ] 跑通本地：`npm run dev`，能打开空白首页
- [ ] 第一次提交并推送到 GitHub

✅ **验收**：本地能跑，代码在 GitHub 上。

---

## 第 5 步：做登录 + 秘书后台（第 2~4 天）

- [ ] 用 Supabase Auth 做登录（手机号或邮箱都行，部门内部建议用手机号 + 验证码或统一账号）
- [ ] 登录后按 role 分流：秘书进后台，员工进手机端
- [ ] **秘书建单页**：一个表单，填 标题/描述/地址/时间/优先级/指派给谁 → 保存到 `tasks`
- [ ] **秘书任务列表页**：按状态和优先级看所有任务，能改状态、能重新指派
- [ ] （可选）邮箱转单：把秘书收邮件的痛点半自动化——后期可做「转发邮件→自动建草稿单」，先不做

✅ **验收**：秘书能在电脑上建单、派单、看到所有任务。

---

## 第 6 步：做员工手机端（第 5~8 天，最核心）

- [ ] **今日任务看板**：登录后默认显示「今天指派给我的任务」，按优先级排序（紧急置顶）
- [ ] **任务详情页**：显示 优先级 / 地址 / 时间 / 故障描述；有「开始任务」按钮（点了记 `started_at`，状态变 `in_progress`）
- [ ] **过程拍照反馈**：详情页里能拍照/选图上传 → 存 Storage，写入 `task_updates(type=progress)`
- [ ] **完工确认闭环**：
  - [ ] 拍完工照片 + 写留言
  - [ ] 电子签字（用 HTML canvas 手写签名，存成图片到 `signatures`）
  - [ ] 提交后状态变 `done`，记录 `completed_at`（精确到分钟）
- [ ] **做成 PWA**：加 `manifest.json` + service worker，让员工能「添加到主屏幕」，用起来像 App

✅ **验收**：员工用手机能完整走完「看单→干活→拍照→签字→完工」。
